# Unveil Idea for Mosaico

This app shares the independent UI/runtime, adding official ESP-Iris/Vibe Mode integration. It installs as .irisfw and runs as the selected native application, rather than inside Works.

## Build

Initialize the pinned firmware/mosaico/third-party/esp-mosaico-utils submodule, install host bundle dependencies, and use the pinned ESP-IDF revision:

```bash
python -m pip install -r requirements-host.txt
source /path/to/esp-idf/export.sh
export ESP_IRIS_PYTHON="$(command -v python)"
idf.py build
cmake --build build --target system-update-bundle
```

The root tools/build_mosaico.py idea initializes dependencies and builds. UV_SHARED_ROOT and MOSAICO_UTILS_ROOT accept explicit staged-build paths; defaults are repository-relative.

Output: build/unveil_idea-system-update.irisfw. It is generated by the official builder, not by renaming a raw binary. Its private unveil resources start at 0x610000, where its own app slot ends. Factory graphics/system ranges and the retained immutable prefix are preserved.

## Install and return

Use compatible Vibe Mode/System Update tooling. Creating a package does not publish it to the store or assign a six-digit download number. System -> Ideas requests return to Vibe Mode; holding AI during power-on is the retained hardware entry.

ESP-Iris owns high-speed USB. The standalone console component is excluded. Wi-Fi and service defaults are blank; first UI readiness participates in retained health reporting. New boot and return behavior still require physical acceptance.

## Optional store submission package

`mosaico-ideas.json`, the 64x64 RGBA icon and bilingual presentation inputs prepare the author-side store metadata. Generating the optional website/store ZIP also needs the owning tools' requirements-ideas.txt and host libraqm >= 0.9. It is separate from the already generated local .irisfw, and no store upload/publication has been performed.
